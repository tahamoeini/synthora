# Market data and forecasting boundary

This application separates market observation from portfolio valuation and planning.

## Live market observations

The Cloudflare market function reads configured public sources and returns normalized quotes:

- Domestic dollar, gold, and silver: TGJU, Bonbast, and the Navasan public data mirror. ChartGoldPrice is a cold standby for gold and silver when primary coverage is degraded or conflicted.
- Crypto: the keyless [CoinMarketCap simple-price API](https://pro.coinmarketcap.com/api/documentation/pro-api-reference/keyless-public-api/), direct [Nobitex Rial market stats](https://apidocs.nobitex.ir/?shell=), Binance, Coinbase, Kraken, and no-key Gold API quotes can contribute public BTC/ETH observations. Kraken also supplies a USDT/USD cross-check; its USD price is converted using the observed domestic dollar rate and compared with Nobitex's direct USDT/Toman price. Nobitex Rial values are divided by 10 to convert rials to toman. Binance's USDT-denominated values are converted only through the direct observed Nobitex USDT/Toman quote; USDT is never assumed equal to USD. Coinbase, Kraken, and Gold API USD values use the observed domestic dollar rate. A user's CoinGecko or CoinMarketCap key adds authenticated crypto quote requests. Platform keys require D1-backed provider budgets.
- Crypto history: public [Nobitex OHLC](https://apidocs.nobitex.ir/market_data/%D8%AF%D8%B1%DB%8C%D8%A7%D9%81%D8%AA-%D8%AF%D8%A7%D8%AF%D9%87-%D9%87%D8%A7%DB%8C-ohlc) supplies daily BTC/IRT, ETH/IRT, and USDT/IRT closes without a key. The endpoint documents a 500-candle page size and a 60-request-per-minute limit; Synthora converts Rial closes to Toman and caches each upstream page at the edge for five minutes. For an all-time request it reads up to 10 pages (5,000 daily observations) per crypto asset. If Nobitex fails, BTC/ETH can fall back to paged Coinbase USD candles, then Binance USDT candles, then Kraken's most recent 720 daily candles, followed by key-backed Gold API history and CoinGecko when configured. Coinbase pages at most 16 chunks of 290 days per request (beginning in 2015); Binance requires a same-date observed Nobitex USDT/Toman value; USD sources require same-date TGJU dollar observations; Kraken does not offer older candles beyond its documented 720-entry window. The optional Gold API history key adds an hourly-limited source when D1 and session signing are configured. Tether history retains Nobitex as primary and can use Kraken USD history only with dated TGJU conversion. Each asset response reports its actual source and available candidates.
- Metals: Metals.live is used for global metal references; [Gold API](https://gold-api.com/docs) adds no-key global quotes for gold, silver, platinum, and palladium. Its [asset page](https://gold-api.com/assets/) lists supported symbols, and the [Gold API pricing page](https://gold-api.com/pricing) currently allows 10 history/OHLC requests per hour on its free tier. A server-side `GOLD_API_KEY` adds daily metal history and USD crypto history, with a D1-backed hourly budget; no key is sent in a URL. Gold and silver histories keep TGJU first and ChartGoldPrice as an existing fallback, then can use Gold API. Platinum and palladium can use Gold API history when configured; Yahoo Finance remains disabled unless its license is confirmed. Copper adds the [FRED monthly IMF benchmark](https://fred.stlouisfed.org/series/PCOPPUSDM), converted from USD per metric ton to Toman per gram using the mean of TGJU daily dollar observations from that month. It is a monthly period-average benchmark, not a daily futures series; coverage reports its monthly cadence and dates with no matching FX are omitted. FRED marks the series “Copyrighted: Citation Required”; point/source metadata attributes “FRED / IMF copper.” Copper's separate Yahoo daily-futures history still requires license confirmation. The TGJU global-metal page scraper is not used: [TGJU's terms](https://www.tgju.org/terms) require written consent to copy or use its site content and prices.
- Tehran market reference: TSETMC and TGJU `gc30` are queried together for current index points. History keeps TGJU first and falls back to the TSETMC TEDPIX index-history endpoint if TGJU history fails. Jalali source dates are converted to Gregorian dates; a source's retrieval time is not substituted for an unknown observation time.
- Fixed-income yield: the displayed annual return is read from one published fund page. It remains a single-source observation; a second fund would be a different product and cannot safely be averaged into the same metric without a defined comparable benchmark.
- Fixed income: the configured fund-provider page.

### Historical source matrix

| Instrument | History sources, in fallback order | Coverage notes |
| --- | --- | --- |
| USD/Toman | TGJU | Other current local FX feeds do not provide an eligible, documented history path for this same free-market rate. |
| 18k gold, silver | TGJU → ChartGoldPrice → Gold API with `GOLD_API_KEY` | USD-based fallback points require a same-date TGJU dollar observation. |
| Bitcoin, Ethereum | Nobitex → Coinbase → Binance → Kraken → Gold API with key → CoinGecko with user/platform key | Binance requires dated USDT/Toman observations; the USD feeds require dated dollar observations. Coinbase is paged to cover up to about 12 years; Kraken exposes only the latest 720 daily candles. |
| Tether | Nobitex → Kraken → CoinGecko with user/platform key | USD-based fallbacks use dated dollar observations; Tether is never treated as exactly one USD. |
| Platinum, palladium | Yahoo Finance with license confirmation → Gold API with key | Yahoo access stays disabled until the operator confirms the applicable use rights. |
| Copper | Yahoo Finance with license confirmation → FRED/IMF monthly benchmark | The monthly benchmark is an observed period average, not a daily futures close; FX conversion uses the mean of observed daily dollar values from the same month. |
| Tehran index (TEDPIX) | TGJU → TSETMC | Index-point reference only; not a tradable holding. |
| Fixed-income yield, cash | No historical price series | Yield is a separate fund metric; cash has no varying market price. A synthetic series is not created for either. |

The endpoint uses the first source that returns enough usable observations; it does not blend price histories across providers. Each asset's `coverage.candidateSources` lists eligible alternatives, while `coverage.source` and point provenance identify the feed actually returned.

Prices are normalized to the unit shown in the response. Direct quotes are distinct from converted quotes; derived values list their dependencies. `observedAt` represents the upstream observation time when the provider supplies one, while `retrievedAt` records when this service read it. Unknown observation time stays unknown; retrieval time is never substituted as observation time.

The `/api/market?assets=...` query accepts allow-listed instrument IDs. It returns only those requested instruments; conversion dependencies such as the domestic dollar and USDT rates are fetched internally. Each returned quote's `configuredSourceCount` records providers actually attempted for that request; it is not a guarantee that each provider returned a quote. Market rows show accepted versus attempted source coverage, and advanced diagnostics show safe, localized provider failure categories. The market page requests every visible market-label asset plus `fixedIncome` and any additional priceable held assets, so its normal request covers the full quote catalog.

Independent provider calls run concurrently with bounded timeouts. Domestic FX and metal fallback providers are requested only when primary coverage is degraded or conflicted; both Tehran index sources are queried together. Provider failure does not discard successful partial data. The initial interactive budget is 3.5 seconds and is included in diagnostics with observed response time.

Quote quality is conservative. A single source is visible with low confidence. Two sources are accepted only when they agree under a calibrated class-specific policy. Three or more sources use the median and median absolute deviation (MAD) to reject outliers. Agreement thresholds have not yet been calibrated against a representative sample, so the current policy treats any remaining disagreement as a conflict. Conflicted prices have no value and are excluded from portfolio valuation. The policy version and calibration state travel with the quote.

The app also exposes `/api/fx?quotes=USD,RUB,CNY` for dated cross-currency references. The browser derives display-only Toman conversions from its accepted Iran-market dollar quote and the returned cross rates. The FX endpoint ignores caller-supplied dollar prices and does not claim a verified Toman conversion; RUB uses the Bank of Russia daily rate, and CNY uses the CFETS observation through Frankfurter. These rates and the Bank of Russia metals series are daily references, not Iranian live retail quotes. Selected provider responses use a shared D1 cache and request coordinator: ordinary sources have a minimum 60-second interval, CoinGecko uses a six-minute cache, authenticated platform CoinMarketCap uses a 15-minute D1 cache, and daily FX sources use a 24-hour cache. Keyless CoinMarketCap responses use a 60-second edge cache; user-key quotes bypass shared provider cache storage. Provider `Retry-After` values extend cooldowns. Stale cache entries are marked; stale quote inputs are excluded from current quote aggregation. This cache is operational coordination, not a canonical durable market-history dataset. Provider candidate lists describe eligible fallbacks, not guaranteed coverage or permission to use; licensed sources remain gated and mismatched periods, units, or FX dates remain unavailable. Copper and fixed-income yield still have one default live reference, though copper now has an additional monthly history benchmark. The Iran-market dollar remains a single-source historical series because other discovered free-market feeds either expose only live data, have unavailable redistribution terms, or require a key in the URL. Do not infer a second fixed-income yield from another fund. Global equities and Iran ticker search remain out of scope until their data contracts are verified. CoinGecko, CoinMarketCap, and Gold API key setup is described in the [Cloudflare API guide](cloudflare-market-api.md). `/api/inflation` supplies an annual World Bank CPI reference, which remains distinct from an investor-selected scenario assumption.

## Portfolio behavior

The catalog separates priceable instruments from strategic sleeves. It defines cash/liquidity, fixed income, gold, FX, Iran equity, global equity, crypto, and commodities. Existing planning keys remain compatible and map as follows: `fixed` to fixed income, `gold` to gold, `currency` to FX, and `silver` to commodities.

The shared planning catalog maps stable IDs to the fixed-income, gold, FX, crypto, and commodity sleeves. The default recommendation remains the original four assets: fixed income, gold, currency, and silver. Copper, platinum, palladium, bitcoin, and ethereum can be opted into each recommendation independently. Selected metals divide the existing commodity allocation by inverse estimated volatility. Selected crypto receives a 1%, 3%, or 5% target for conservative, balanced, or growth profiles; bitcoin and ethereum divide that target by inverse volatility, and their combined weight never exceeds 5%. Tether is available only in the manually weighted simulation; the Tehran index is an indicator, not an investable instrument.

Simulation accepts all catalog planning assets plus Tether, with newly added assets at zero weight by default. It uses the per-asset expected-return and volatility assumptions stored in model settings when observed history is insufficient. These are editable scenario inputs, not asserted forecasts. Existing portfolio assets and old recommendation records are preserved; assets introduced after an older record are treated as zero weight. Recommendations are previews until the user explicitly saves one. They only allocate new monthly contributions and do not sell or modify holdings or transactions.

Backtests use observed monthly price history only. Modeled fallback returns are never presented as historical data. A selected asset with missing or discontinuous observations makes the requested backtest unavailable, and the UI identifies the missing coverage rather than filling it with assumptions. Long crypto backtests may therefore be unavailable when the provider does not offer enough historical data.

## Hosted models and prediction boundary

The production app does not call Hugging Face or another hosted model to predict asset prices. It does not require a hosted-model token or present model output as a price prediction. The versioned return and risk assumptions in `src/engine.js`, observed historical inputs, Monte Carlo paths, and goal projections are planning scenarios; their outputs must not replace a current market quote, transaction price, or portfolio valuation. A hosted forecasting feature would change the product's stated boundary and needs a separate product and model review before it is proposed as user-facing behavior.

The existing Gaussian Monte Carlo baseline remains available. Additional versioned methods include 12-month-half-life EWMA volatility (`mc-ewma-v1`) and a three-month moving-block bootstrap (`mc-block-bootstrap-v1`). Walk-forward comparisons use a 24-month training window and require at least 24 out-of-sample forecasts before enabling either method. Otherwise, the baseline stays active. These are method-selection gates, not a claim that the models predict future returns.

Simulation and backtest run only after the analysis view is opened and execute in a browser Web Worker. Navigation and changed planning inputs cancel stale work. Goal planning uses the same simulation model for success probability, P10/P50/P90, an inflation-adjusted target, and a binary search for required monthly contributions. Goal projections use planning assets; unsupported personal holdings are shown as excluded.
